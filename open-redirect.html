INSPECT THE SOURCE

Where the bug lives

JAVASCRIPT
VULNERABLE CODETRUSTED INPUT
function vulnerableRedirect(destination) {  return {    status: 302,    location: destination,    accepted: true  };}const decision = vulnerableRedirect(userInput);renderDecision(decision); // local preview only

Why it is unsafe: the handler returns a redirect destination directly from untrusted input. A real server might place it in a Location response header.

FIXED CODEALLOWLIST
const ALLOWED = new Set(["/dashboard", "/reports", "/help"]);function fixedRedirect(destination) {  if (!ALLOWED.has(destination)) {    return { status: 400, location: null, accepted: false };  }  return { status: 302, location: destination, accepted: true };}const decision = fixedRedirect(userInput);renderDecision(decision); // local preview only

Why it works: only exact local paths on the allowlist are accepted. External and ambiguous destinations fail closed.

WHAT IT IS

A trusted domain as a detour

An open redirect trusts a visitor-supplied URL and sends them there without validation. A phishing link can hide behind a familiar domain.

OWASP: Top 10:2025 A01 (Broken Access Control), which lists CWE-601. CWE: CWE-601.

WHY IT MATTERS

Trust can be borrowed

A visitor may trust the first domain, then land on a lookalike site. Redirects can support phishing or OAuth abuse, but do not alone steal credentials.

DOCUMENTED CASECVE-2022-28923

NVD documents Caddy v2.4.6's open redirect (CVE-2022-28923), which could send users to phishing sites; this does not establish a victim compromise.

THE FIX

Allow only known paths

  • Prefer a destination ID mapped to a local path.
  • For local redirects, use a framework's local-URL helper.
  • If external targets are essential, compare parsed URL components against an explicit allowlist.

Do not rely on string prefix checks such as startsWith("https://trusted.example").
