LAB 01 / JAVASCRIPT OBJECTS

Prototype Pollution

An unsafe merge can write attacker-controlled keys through a special property and change what other objects appear to contain. This lab uses a private prototype object so the effect is visible without touching the browser's global Object.prototype.

INSPECT THE SOURCE

Where the bug lives

JAVASCRIPT
VULNERABLE CODERISKY LINE
function vulnerableMerge(target, source) {  for (const key of Object.keys(source)) {    const value = source[key];    if (value && typeof value === "object") {      const child = target[key] || {};      target[key] = vulnerableMerge(child, value);    } else {      target[key] = value;    }  }  return target;}const base = {};const target = Object.create(base);vulnerableMerge(target, JSON.parse(payload));

Why it is unsafe: the merge reads target[key] without checking whether the key is special. For __proto__, it recurses into the target's prototype.

FIXED CODEGUARD LINE
const BLOCKED_KEYS = new Set(["__proto__", "prototype", "constructor"]);function safeMerge(target, source, rejected = []) {  for (const key of Object.keys(source)) {    if (BLOCKED_KEYS.has(key)) { rejected.push(key); continue; }    const value = source[key];    if (value && typeof value === "object" && !Array.isArray(value)) {      const child = Object.prototype.hasOwnProperty.call(target, key) ? target[key] : Object.create(null);      target[key] = child;      safeMerge(child, value, rejected);    } else target[key] = value;  }  return rejected;}const target = Object.create(null);const rejected = safeMerge(target, JSON.parse(payload));

Why it works: special keys are rejected before recursion, and the destination has no inherited prototype to traverse.

WHAT IT IS

Changing the chain

JavaScript objects can inherit properties from another object called a prototype. Prototype pollution happens when untrusted input changes that prototype, so code may see properties it never set itself.

OWASP: WSTG-INJT-22 (testing reference). CWE: CWE-1321. No direct OWASP Top 10 category is claimed here.

WHY IT MATTERS

Unexpected trust

If application code treats an inherited flag as an authorization decision, an attacker may influence behavior, expose data, or cause a crash. The impact depends on a later piece of code that uses the polluted property.

DOCUMENTED CASECVE-2020-8203

IBM documented prototype pollution in affected lodash/UrbanCode Velocity components, with denial of service as a concern. This is a published vulnerability advisory, not a claim of confirmed in-the-wild exploitation.

THE FIX

Reject dangerous keys

  • Reject __proto__, constructor, and prototype.
  • Build data objects with Object.create(null) when suitable.
  • Validate input shape and avoid unsafe recursive merges.

The demo resets its private objects for every run. It never mutates Object.prototype.
